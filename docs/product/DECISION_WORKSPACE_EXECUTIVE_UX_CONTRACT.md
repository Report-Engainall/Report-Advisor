# DECISION WORKSPACE — EXECUTIVE UX CONTRACT
## 2026-10-02

## Goal
Turn a Smart Report finding into a trustworthy action without forcing the user to understand internal system mechanics.

## Primary reading order
1. WHAT HAPPENED
2. WHY / CONTRIBUTION
3. SO WHAT / IMPACT
4. WHAT NEXT
5. PROOF
6. DECISION / APPROVAL
7. WORK / OUTCOME

The UI must preserve the user's position and the report context through the journey.

## Insight card contract
Every material insight card exposes:
- headline in business language;
- metric/value + period;
- state badge: observed / derived / inferred / recommended;
- evidence affordance;
- limitation state when relevant;
- next decision question;
- action entry when allowed.

## Proof drawer
The proof drawer shows, in compact form:
`SOURCE` → `IMPORT JOB` → `SOURCE HASH` → `EVIDENCE SNAPSHOT` → `CALCULATION` → `LIMITATION`

Technical identifiers remain available without overwhelming the primary business view.

## Decision flow
`INSIGHT`
→ `REVIEW EVIDENCE`
→ `ACCEPT / MODIFY / REJECT`
→ `APPROVAL`
→ `CREATE WORK`
→ `TRACK OUTCOME`

Decision UI must distinguish:
- recommendation generated by the system;
- decision made by a human;
- approval granted by an authorized actor;
- work actually created;
- outcome actually observed.

## Failure states
No generic silent failure.

`LOADING`:
Show what is being prepared.

`EMPTY`:
Explain why there is no business result.

`NOT_AVAILABLE`:
State the missing business input.

`INSUFFICIENT_SAMPLE`:
State the minimum evidence threshold that was not met.

`REVIEW_REQUIRED`:
Explain what needs human verification.

`BLOCKED`:
State the policy/permission/evidence blocker and the next permitted action.

## RTL and responsive behavior
- Preserve semantic hierarchy in RTL.
- Keep business values visually dominant over technical metadata.
- Never place source/evidence metadata where it competes with the decision itself.
- On narrow screens collapse proof details into a drawer, not a separate workflow.

## Acceptance
For one real verified insight, a user can traverse:
`WHAT → WHY → PROOF → WHAT NEXT → DECISION → APPROVAL → WORK → OUTCOME`
and return to the same report context with all lineage intact.
